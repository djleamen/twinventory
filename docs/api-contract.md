# Twinventory Backend Contract

This document defines the integration boundaries that are implemented. It does not define the raw Shopify payload or ingestion transport. Shopify data must be normalized into the product document below before indexing.

## Shared Embedding Contract

- Model: `EMBEDDING_MODEL` (`text-embedding-3-small` by default)
- Dimensions: `EMBEDDING_DIMENSIONS` (`1536` by default)
- Similarity: cosine
- Both indexed product embeddings and recommendation query vectors must use the same model and dimensions.
- A vector with the wrong number of values is rejected.

Vector arrays in the examples below are abbreviated. Real payloads must contain exactly `EMBEDDING_DIMENSIONS` values.

## Product Ingestion Contract

Owner handoff: Fiona supplies product records, Devyansh supplies tags and embeddings, and DJ owns normalization into Elasticsearch.

The current ingestion boundary is the Python function:

```python
from services.elastic_client import index_product

index_product(product)
```

Each normalized product document has this shape:

```json
{
  "product_id": "shopify-product-or-variant-id",
  "title": "Black satin midi dress",
  "description": "Bias-cut formal dress",
  "image_url": "https://cdn.example.com/dress.png",
  "category": "dress",
  "color": "black",
  "style": "formal",
  "tags": ["wedding", "evening", "satin"],
  "embedding": [0.012, -0.031],
  "shop_url": "https://shop.example.com/products/dress",
  "price": 129.99,
  "currency": "USD"
}
```

Required fields:

| Field | Type | Contract |
| --- | --- | --- |
| `product_id` | string | Stable and unique. Used as the Elasticsearch document ID, so re-indexing updates the product. |
| `title` | string | Human-readable product name and highest-weight lexical search field. |
| `image_url` | string | Public product image used by recommendation cards. |
| `category` | string | Lowercase normalized exact-match filter, such as `dress`, `shirt`, or `shoes`. |
| `color` | string | Lowercase normalized exact-match filter. |
| `style` | string | Lowercase normalized exact-match filter, such as `formal` or `casual`. |
| `tags` | string array | Searchable normalized descriptors. |
| `embedding` | number array | Exactly 1536 values unless `EMBEDDING_DIMENSIONS` changes. |
| `shop_url` | string | Public purchase link. |
| `price` | number | Price in the currency's major unit, such as `129.99`. |
| `currency` | string | Uppercase ISO 4217 code, such as `USD`. |

Optional field:

| Field | Type | Contract |
| --- | --- | --- |
| `description` | string | Searchable product copy. Use an empty string when unavailable. |

The adapter from Shopify or another source is intentionally pending. It must output this normalized shape rather than passing a provider-specific object to `index_product()`.

## Recommendation Query API

### `POST /recs/query`

Searches the Elasticsearch `products` index using vector similarity plus optional lexical text and exact-match filters.

Request:

```json
{
  "query_vector": [0.012, -0.031],
  "query_text": "outfit for a summer wedding",
  "category": "dress",
  "color": "blue",
  "style": "formal",
  "limit": 12
}
```

| Field | Required | Contract |
| --- | --- | --- |
| `query_vector` | yes | Number array with exactly `EMBEDDING_DIMENSIONS` values. Generated by Devyansh's prompt or style-vector pipeline. |
| `query_text` | no | Expanded search text. Searches `title`, `tags`, and `description`; `title` has the highest lexical weight. |
| `category` | no | Exact lowercase filter. |
| `color` | no | Exact lowercase filter. |
| `style` | no | Exact lowercase filter. |
| `limit` | no | Integer from 1 through 50; defaults to 12. |

Response:

```json
{
  "results": [
    {
      "product_id": "shopify-product-or-variant-id",
      "title": "Black satin midi dress",
      "image_url": "https://cdn.example.com/dress.png",
      "category": "dress",
      "color": "black",
      "style": "formal",
      "tags": ["wedding", "evening", "satin"],
      "shop_url": "https://shop.example.com/products/dress",
      "price": 129.99,
      "currency": "USD",
      "score": 1.25
    }
  ]
}
```

- The stored `embedding` is never returned.
- `score` is for ranking within one response and must not be displayed as a percentage.
- Invalid vector length or `limit` returns HTTP 422.
- A search-service failure currently returns HTTP 500.

The endpoint does not parse prompts or create embeddings. Person B owns those steps and sends the resulting vector and optional expanded text to this endpoint.

## Inventory Storage Contract

MongoDB is inventory-only for the demo. The database is `twinventory`, the collection is `items`, and there is no application `users` collection.

Person B writes normalized inventory documents with this shape:

```json
{
  "user_id": "demo-user",
  "image_url": "https://cdn.example.com/item-cutout.png",
  "category": "shirt",
  "color": "white",
  "style": "casual",
  "embedding": [0.012, -0.031],
  "created_at": "2026-09-19T17:00:00Z"
}
```

- `user_id` remains required even with one demo user so reads stay deterministic.
- `created_at` must be stored as a MongoDB datetime, not a formatted string; the string above shows the wire representation.
- The collection is indexed by `user_id` ascending and `created_at` descending.
- The shared collection accessor is `services.mongo_client.get_items_collection()`.

## Health API

### `GET /health`

Success, HTTP 200:

```json
{
  "mongodb": "ok",
  "elasticsearch": "ok"
}
```

If either dependency cannot be reached, the endpoint returns HTTP 503 and marks that dependency as `unavailable`. No credentials or connection details are returned.
